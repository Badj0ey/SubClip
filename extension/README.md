# SRT 字幕助手 · B站桥接（浏览器插件）

把 B 站页面的视频信息与字幕，桥接给本地桌面端「SRT 字幕检索与视频切片辅助工具」。

适用于 Chrome / Edge 等 Chromium 内核浏览器（Manifest V3，要求 116+）。

---

## 一、安装

1. 先启动桌面端（`npm run dev` 或已打包的 exe），确认右下角/顶栏显示 **🔌 插件未连接**。
   在桌面端「设置 → 浏览器插件通信」里可以点 **打开** 直接定位到本目录。
2. 浏览器地址栏输入：
   - Chrome：`chrome://extensions`
   - Edge：`edge://extensions`
3. 打开右上角 **开发人员模式**。
4. 点 **加载解压缩的扩展**，选择本目录（`app/extension`）。
5. 加载完成后，点击扩展图标即可打开面板。建议「固定」到工具栏便于使用。

## 二、使用

> **同步是手动的**：插件实时识别当前页面、实时读取登录状态，但只有你点按钮时才会把页面数据
> 推给桌面端。这样可以避免浏览网页时不停往桌面端塞数据。
> 唯一会自动做的是「登录状态」（可在设置里关掉）—— 因为它是拉取字幕的前置条件。

### 2.1 弹窗（点扩展图标）

主视图只有一件正事：**同步到桌面端**（一个按钮，按页面类型自动决定做什么）。

| 你所在的页面 | 点「同步到桌面端」会发生什么 |
| --- | --- |
| 视频页 / 播放页 | 同步该视频，并**连所有分P一起**拉取字幕 |
| 合集 / 系列 / 收藏夹 / UP主投稿页 | 把整份清单交给桌面端，桌面端弹出确认框让你挑 |

- 顶部只有两个小图标：`⟳` 重新连接、`⚙` 设置。
- 端口、配对令牌、自动同步开关都收进 `⚙` 设置页，平时看不见。
- 首次使用：连上桌面端后会自动把浏览器登录状态同步一次（之后桌面端就能自己调接口拉字幕）。
  不想自动同步就在设置里关掉，改点「立即同步登录状态」。

### 2.2 页面左下角的 ♪ 悬浮工具箱

视频页和直播间左下角有个半透明小圆点，点一下展开面板，再点 `×` 收起。
**它不打扰页面**：不展开时只占 34×34 像素。

面板里能做的事：

- **只放音频（省流量）** —— 核心功能，见下节。
- **音质**（视频页）/ **画质**（两个页面都能选）—— 见 2.3。
- **播放 / 暂停、音量、进度**（进度只在视频页有）。
- **弹幕 +1**（仅直播间）—— 见 2.4。
- **同步到桌面端** —— 和弹窗里那个按钮等价。

### 2.3 只放音频（省流量）

**视频页**：勾上后原生 `<video>` 被暂停（不是隐藏，是真暂停），视频轨彻底停止下载；
插件自己从 DASH 里挑一条音频流，按 SIDX 分片索引只取音频字节，用 MediaSource 喂给一个
隐藏的 `<audio>`。实测同一个视频 213 秒：只放音频约 2.7 MB，1080P 视频要几十 MB。

播放器区域会盖一层黑色覆盖层（封面 + 标题 + 「画面已停止以节省流量」），点 `×` 或取消勾选即恢复画面。

**直播间**：勾上后向 B 站要 `only_audio=1` 的 **FLV 纯音频流**（实测 0 个视频 tag），
用内包的 mpegts.js 播放，并停掉页面原生播放器。

> 已知边界：少数房间（刚开播 / 未转码）不提供纯音频流，此时会明确报错**并自动回退到最低画质**，
> 而不是静默失败。CDN 节点抽风时会在 12 秒无进度后自动换下一个候选节点。

### 2.4 画质

- **视频页**：档位由播放器自己给出（1080P 高码率 / 1080P 高清 / 720P / 480P / 360P…），
  切换走 `player.requestQuality()`。只放音频时切它不影响当前流量，但**切回画面时就是这一档** ——
  适合「先选好低画质再恢复画面」。
- **直播间**：档位来自房间的 `g_qn_desc`（杜比 / 4K / 原画 / 蓝光 / 超清 / 高清 / 流畅）。
  纯音频流本身没有画质概念，这里控制的是「万一要退回视频流」时的档位。

拿不到档位时整行会隐藏，不会留一个点了没反应的死控件。

### 2.5 弹幕 +1 / 复制（仅直播间）

鼠标悬停在任意一条弹幕上，右侧出现两个小按钮：

- **复制** —— 把这条弹幕的文本放进剪贴板（原来是「偷」的叫法，改成更直白的「复制」）。
- **+1** —— 把这条弹幕原样重发出去。带 1 秒硬间隔队列，连点不会触发 B 站限流。

前提：浏览器里已登录 B 站（发送需要 `bili_jct` 这个 Cookie）。没登录会明确提示，不会假装发出去了。

## 三、工作原理

插件在**三个世界**里各放一部分代码，边界划得很死（每个都吃过亏才这么分）：

```
B站页面
  ├─ 隔离世界（ISOLATED）
  │    content.js      识别页面类型，提取 BV号 / 标题 / UP主 / 分P；调 B 站接口取字幕轨
  │    agent.js        「♪ 工具箱」面板：音频模式 / 画质 / 弹幕 +1 / 同步按钮
  │    live-audio.js   直播纯音频（FLV + mpegts.js）
  │    audio-player.js 视频纯音频（DASH + SIDX + MediaSource）
  │    live-danmaku.js 弹幕「复制 / +1」按钮注入
  │
  ├─ 主世界（MAIN）—— 只做隔离世界做不到的事
  │    page-bridge.js  stopPlayback() 停原生播放器、requestQuality(qn) 切画质
  │                     （这些对象挂在页面的 window 上，隔离世界看不见）
  │
  └─ background.js     service worker
       ├─ 调度：找一个 bilibili.com 标签页，把接口调用交给它执行
       ├─ 下载字幕 JSON（hdslb.com CDN，不需要登录态）
       └─ WebSocket 客户端 → ws://127.0.0.1:8765（桌面端）
```

隔离世界与主世界之间用页面上的 `CustomEvent`（`subclip:bridge` / `subclip:bridge-reply`）通信，
带自增 `id` 配对，**4 秒超时**兜底 —— 主世界没注入（比如改坏了 manifest）时不会永久挂住。

### 为什么接口调用必须放在页面里，而不是 service worker

这是本项目踩过的最大一个坑：

B 站的登录凭证 `SESSDATA` 通常是 `SameSite=Lax`。而 service worker 发起的请求，对 `bilibili.com` 而言属于**跨站请求**（发起方是 `chrome-extension://`），浏览器会拒绝携带该 Cookie —— 于是接口以「未登录」身份返回，**字幕列表永远是空的**。

而内容脚本运行在页面里，`www.bilibili.com → api.bilibili.com` 属于**同站**（SameSite 看的是可注册域），Cookie 与 Referer 都天然正确。

所以现在的分工是：

| 环节 | 执行位置 | 原因 |
| --- | --- | --- |
| `x/player/wbi/v2`（取字幕轨） | **页面上下文** | 需要登录态 Cookie |
| `x/web-interface/view`（取 cid/分P） | **页面上下文** | 同上 |
| 字幕 JSON 下载 | 扩展 service worker | 公开 CDN，不需 Cookie；扩展请求不受 CORS 限制 |

> 参考项目 `bili_subtitle_extension_native` 采用的是不同但等价的思路：用 `chrome.cookies.getAll()` 把 Cookie 显式读出来，交给本地 Python 进程去请求。本质上都是**绕开扩展自身的跨站 Cookie 限制**。

### 其他要点

- **WBI 签名**：新接口需要 `w_rid` 签名。Web Crypto 不提供 MD5，插件的 `content.js` 内置了一份纯 JS MD5（已用 Node `crypto` 逐位比对验证），并按 B 站的 `mixinKeyEncTab` 做密钥重排。
- **请求头注入**：`declarativeNetRequest` 动态规则给 `hdslb.com` 的请求补上 `Referer` / `Origin`（浏览器禁止脚本直接设置这两个头）。
- **没有 B 站标签页时**：会自动开一个后台标签页完成接口调用，用完即关。
- **纯音频为什么要碰主世界**：原生播放器对象（`window.player` / SistersPlayer）只在主世界可见。
  隔离世界能做的只是 `video.pause()`，但视频轨是否真的停止拉流取决于播放器自己的状态。
  停原生流 + 切画质都必须走主世界。
- **直播取流端点**：用的是 `xlive/web-room/v2/index/getRoomPlayInfo`。
  `xlive/app-room/v2/...`（很多老教程/脚本在用）自 2026 年起对所有参数组合返回 `-400 请求错误`。
- **URL 参数不要传错**：接口只认数字 `room_id`，传整条 `location.href` 会得到 `-400`，
  而界面上的报错文案就是「请求错误」，几乎无法定位。现在统一走 `toRoomId()` 收口，并有单测锁住。
- **保活**：MV3 的 service worker 会被浏览器回收，插件用 `chrome.alarms` 每分钟唤醒一次并重连；连接断开时按 1s → 1.6 倍退避重连（上限 30s）。

## 四、协议

与桌面端共享，定义见 `shared/protocol.js`（桌面端对应 `src/shared/bridge.ts`）：

- **当前协议版本：5**
- v2 的改动：UP主 字段由 `uploader.mid` 改为 `uploader.uid`（B站接口里仍叫 `owner.mid`）。
  桌面端读取时会兼容旧字段名，所以插件没更新也不会立刻坏掉。
- v3 的改动：桌面端会**校验握手来源**，只放行本扩展；`hello` 里新增可选 `token`（配对令牌）。
  扩展 ID 由 `manifest.json` 的 `key` 字段钉死为 `lmchilpnlhdfbpjklnfpfgkbddcdekpl`，
  桌面端的白名单与它一一对应（`npm run test:wbi` 会校验两者一致）。
- v4 的改动：新增 `pull-request` —— 插件只上报 BV 号，**抓取交给桌面端**，
  这样不管用户在哪个分P 触发都会拉到全部分P。
- **v5 的改动：统一信封 + 能力表**（第七阶段）：
  - 每条消息都可带 `v`（协议版本）与 `caps`（能力表），两端的 `serialize()` **自动补**，
    业务代码不必手写；
  - `hello-ack` 会带上桌面端的能力表，插件据此**逐项**判断功能是否可用，
    而不是只看版本号（版本号只能表达整体兼容性，实际常常是部分功能不同步）；
  - **缺 `v` 按 1 处理，只用于协商、不用于拒绝** —— 版本号不是断连的理由。

### 能力表

| 能力名 | 含义 | 谁声明 |
| --- | --- | --- |
| `pageInfo` | 能识别页面并上报 | 插件 |
| `subtitle` | 能抓取并推送字幕 | 插件 |
| `cookies` | 能同步 B站登录凭证 | 插件 |
| `pullRequest` | 能请求桌面端拉取全部分P | 插件 |
| `requestSubtitles` | 能接受「抓取某一 P」的指令 | 两端 |

协商规则（**宽限期语义**，桌面端一侧的实现见 `src/main/bridge.ts`）：

- 插件**完全没声明能力表**（v4 及更早）→ 桌面端视为老客户端，**照旧放行**；
- 插件**声明了**能力表却没声明某能力，却发来对应消息 → 桌面端丢弃并记一条日志。

> 这个「宽限期」是刻意设计的：如果写成「没声明就丢弃」，一次协议升级就会让所有老插件
> 失去页面识别与字幕推送 —— 那是拿升级换掉既有功能。
>
> 另外，桌面端对**不认识的消息类型**依然是静默丢弃的，所以插件不能靠「发送成功」判断
> 功能可用，必须看 `hello-ack.protocol` 与 `hello-ack.caps`。

> **为什么必须校验来源**：WebSocket 握手不受 CORS 约束，任何网页都能连 `ws://127.0.0.1:端口`。
> 只绑回环地址挡不住本机网页，所以来源校验是这里的关键一道闸门。

如果要启用配对令牌：在桌面端「设置 → 浏览器插件通信 → 配对令牌」点「生成」，
把生成的值粘贴到插件弹窗的「配对令牌」里保存即可（留空表示不校验）。

| 方向 | 消息 |
| --- | --- |
| 插件 → 桌面端 | `hello`、`page-info`、`subtitle`、`cookies`、`pull-request`、`log`、`ping` |
| 桌面端 → 插件 | `hello-ack`、`request-subtitles`、`ack`、`pong` |

`page-info` 载荷：

```json
{
  "pageType": "video",
  "bvid": "BV1GJ411x7h7",
  "title": "视频标题",
  "url": "https://www.bilibili.com/video/BV1GJ411x7h7",
  "page": 1,
  "cid": 123456,
  "uploader": { "uid": 703007996, "name": "UP主", "avatar": null },
  "seasonId": 8888,
  "seasonTitle": "合集名",
  "tracks": [{ "lang": "zh-CN", "label": "简体中文（AI）" }]
}
```

`subtitle` 载荷：

```json
{
  "bvid": "BV1GJ411x7h7",
  "page": 1,
  "lang": "zh-CN",
  "label": "简体中文（AI）",
  "cues": [{ "from": 1.5, "to": 3.2, "content": "字幕正文" }]
}
```

## 五、故障排查

| 现象 | 处理 |
| --- | --- |
| 面板显示「未连接桌面端」 | 确认桌面端已启动；在面板里点 ⟳ 重连；确认端口与桌面端设置一致（默认 8765） |
| 桌面端提示端口被占用 | 在桌面端设置里换一个端口，插件面板里同步改 |
| 抓取字幕提示「没有可用字幕」 | 该分P 确实无 CC 字幕，或未登录 B 站，或为付费/受限内容 |
| 抓取字幕提示 403 / 412 | B 站风控。稍等片刻再试，避免短时间大量请求 |
| 面板信息不更新 | B 站页面结构改版可能导致选择器失效，需要更新 `content.js` 里的选择器 |

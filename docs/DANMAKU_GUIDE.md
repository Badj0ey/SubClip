# 弹幕参考（3.17.0）

右侧「剪辑助手」里的「弹幕参考」用于**辅助定位字幕**：先把视频弹幕读出来，按分 P、关键词或当前时间附近筛选，再点击某条弹幕跳到对应字幕。它不是弹幕播放器，也不会把弹幕写进素材库。

## 怎么用

1. 在素材库打开一条 **B 站视频**的字幕文档（文档必须关联 BV 号）。
2. 在右侧「剪辑助手」的「当前字幕」下方点开「弹幕参考」。面板默认折叠，**只有展开时才发起弹幕请求**。
3. 默认跟随当前字幕分 P，并只显示当前字幕时间前后 90 秒内的弹幕，按离当前时间由近到远排序；可以：
   - 输入关键词筛选弹幕正文；
   - 切换分 P；
   - 关闭「当前分P附近 ±90 秒」，查看该分 P 的全部已读取弹幕。
4. 点击一条弹幕：阅读光标移到同分 P 最近的字幕（落在区间内优先，否则取最近边缘），并滚动到该条。**不会改变已勾选的字幕集合。**
5. 如果同一分 P 的视频预览已经打开，点击弹幕还会顺带把播放器跳到弹幕时间；没有打开预览时不会为了跳转去请求视频流。
6. 弹幕缓存 10 分钟。接口出错或弹幕有更新时，点「重新获取」强制刷新。

## 数据从哪里来

- 主进程先通过 B 站视频信息接口拿到各分 P 的 `cid` 与时长。
- 再按 **6 分钟一段**请求分段弹幕接口：

  ```text
  https://api.bilibili.com/x/v2/dm/web/seg.so?type=1&oid={cid}&segment_index={n}
  ```

  返回的是 protobuf（`DmSegMobileReply`）。解析字段以 bilibili-API-collect 为准：`progress=2`（毫秒）、`mode=3`、`color=5`、`content=7`、`idStr=12`。
- 某个分 P 的所有分段都失败时，回退到旧 XML 接口：

  ```text
  https://comment.bilibili.com/{cid}.xml
  ```

  XML 的 `<d p="time,mode,fontsize,color,ctime,pool,midHash,dmid">` 中，`p[7]` 是弹幕 id。
- 请求带 `User-Agent` 与 `Referer: https://www.bilibili.com/`；设置里填了 B 站 Cookie 时会一并带上。没有 Cookie 也可能成功，但受视频、地区和接口策略影响。
- 视频信息里的弹幕总数（`stat.danmaku`）为 0 时不再请求分段：弹幕池本来就是空的，直接返回空结果并说明原因。

## 边界与限制

| 项目 | 当前行为 |
| --- | --- |
| 入库 | **不写入 SQLite**；只在主进程内存里缓存 10 分钟，最多 8 个视频 |
| 剪辑 | 弹幕不参与选区、切片、导出或发布素材包 |
| 分段上限 | 一次最多请求 80 个 6 分钟分段（跨分 P 合计） |
| 条数上限 | 一次最多返回 15,000 条 |
| 时间预算 | 一次读取总预算约 60 秒；剩余不足 800ms 不再发新请求，返回已拿到的部分 |
| 并发 | 最多 4 个分段同时请求，单请求 15 秒超时 |
| 响应大小 | 单个响应上限 8MB |
| 正文长度 | 单条弹幕正文最多保留 500 字 |
| 列表 | 面板最多渲染 350 条；超出时底部会提示匹配数与显示数 |
| 直播回放 | 视频弹幕池里只有投稿者后来加的少量弹幕；直播期间的聊天弹幕**不会**迁移进来，B站也没有公开的回放弹幕存档接口。弹幕总数为 0 时面板直接说明是直播回放，不再发分段请求 |

失败只影响面板：字幕阅读、编辑、选段和切片都不依赖弹幕。面板会显示错误或 `warnings`，不会把失败包装成“没有弹幕”；空结果也会区分「直播回放」「该视频没有弹幕」和「接口暂不可用」，不会一律说成接口故障。

## 工程改动

| 文件 | 作用 |
| --- | --- |
| `src/shared/danmaku.ts` | 纯解析：`parseDanmakuSegment`（protobuf）与 `parseDanmakuXml`（XML），不依赖 Electron |
| `src/main/danmaku.ts` | 抓取、分 P 规划、并发/超时/预算、XML 回退、内存缓存、条数限制 |
| `src/main/ipc.ts` | `bili:danmaku` IPC，校验 BV 号并统一返回 `OpResult` |
| `src/preload/index.ts` | `getDanmaku(bvid, force?)` 类型化入口 |
| `src/renderer/src/components/DanmakuPanel.vue` | 折叠面板、筛选、点击定位字幕 |
| `src/renderer/src/components/ClipPanel.vue` | 在剪辑助手中挂载弹幕面板 |
| `src/shared/types.ts` | `DanmakuItem` / `DanmakuResult` |
| `tests/danmaku.test.ts` | 按真实字段编码的 protobuf/XML 回归测试 |

解析器放在 `src/shared/` 是为了让测试用普通 Node 就能跑，不需要启动 Electron；网络请求留在主进程，渲染进程拿不到任意 URL 的请求能力。

## 与整合包的差异

`SubClip_字幕弹幕联动_完整源码包.zip` 提供了最初版本。合入时做了这些修正，避免把已知问题带进主分支：

- **修正 protobuf 字段**：整合包把 `color` 读成 field 4、`id` 读成 field 8；真实协议是 `color=5`、`idStr=12`。旧写法会把字号当颜色、把时间戳当 id。
- **解析器抽到 shared**：主进程只保留抓取与组装；测试不需要 Electron，类型也不再在 `main/danmaku.ts` 和 `shared/types.ts` 各定义一份。
- **改为展开后加载**：整合包在打开任一字幕文档时就自动读取，长视频可能在后台发出几十个请求；现在只有用户展开面板才读取。
- **面板移到剪辑助手**：整合包把面板插在字幕阅读区底部，展开后会明显挤压字幕列表；现在放在右侧「剪辑助手」，并让「附近」结果按时间距离排序，避免 350 条上限先塞满 0 秒附近的弹幕。
- **有限并发与总预算**：串行改为最多 4 路并发，并加 60 秒总预算、15 秒单请求超时和 8MB 响应上限。
- **强制刷新**：新增 `force` 参数，「重新获取」可以跳过 10 分钟缓存。
- **挂载条件与文案**：只对有关联 BV 号的字幕显示；`aria-label` 从「直播回放弹幕」改为「弹幕参考」，避免把普通投稿误称为直播回放。
- **测试接入 npm**：`test:danmaku` 加入 `npm test`，fixture 覆盖真实字段、XML 实体、空文本、缺时间和截断数据。

## 验证情况（2026-10-24）

- `npm run typecheck` 通过。
- `npm test` 通过：core 181、refactor 6、wbi 20、slice 14、danmaku 解析断言、smoke 45、bridge 38，均 0 失败。
- `npm run build` 通过。
- 真实接口抽样：`oid=1176840&segment_index=1` 返回 HTTP 200、1,239,109 字节；共享解析器解析出 5,867 条，首条 `id=328008371`、`time=40.607`、`color=16750950`，颜色 250 种、非白色 4,503 条、无空 id，mode 覆盖 1/5/4/7。这个结果同时验证了 `color=5` / `idStr=12` 的修正。
- Electron GUI 冒烟（生产构建的 `out/`，临时 `userData`）：通过桥接注入一条测试字幕，展开面板后真实读到 1,404 条；默认「附近 ±90 秒」匹配 820 条、显示前 350 条，首屏是 37–38 秒的弹幕。点击 37 秒弹幕把光标定位到 38–41 秒字幕，播放器跳到 37.978 秒，选区仍为 0 条；字幕列表高度保持 356px，没有被面板挤压。

未覆盖：真实账号登录后的受限弹幕、直播回放全量、超长多 P 视频的 80 段上限场景、安装包内 GUI 实测。接口和视频权限变化可能导致结果与抽样不同。
